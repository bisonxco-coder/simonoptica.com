Явне керування сайтами з настільної програми. Slug antyspam-wp і namespace wpsm/v1 збережені.

== Підключення ==

Після звичайного входу адміністратор може явно підключити програму через POST /wp-json/wpsm/v1/connection:
HTTPS, дійсний cookie-сеанс, X-WP-Nonce для wp_rest, права manage_options/create_users/promote_users.
Обмеження editable_roles також мають дозволяти адміністратору призначення ролі administrator.
Тіло — JSON з полем key: випадковий 256-бітний URL-safe ключ (43 символи), створений програмою.
Сайт зберігає лише SHA-256, час створення та використання. Ключ не повертається і не показується.
У WordPress немає додаткових форм налаштування: стан доступний в «Інструменти → Plugin Control Panel».

Ключ передається лише заголовком X-WPSM-Key по HTTPS. Він дозволяє GET /wpsm/v1/ping,
POST /wpsm/v1/admins і DELETE /wpsm/v1/connection. Ключ не вмикає та не обертає інший ключ,
не авторизує користувача глобально та не надає доступу до стандартних маршрутів wp/v2.
DELETE відкликає підключення; повторне вмикання/обертання потребує cookie-сеансу адміністратора.

Видалення користувача WordPress не відкликає окреме сервісне підключення.
Відкличте його у програмі або деактивуйте плагін. Деактивація видаляє авторизацію;
повторна активація потребує нового підключення. Видалення плагіна очищує також журнал метаданих.

== Створення адміністратора ==

POST /wp-json/wpsm/v1/admins приймає лише JSON: username, email, password, необов’язкове display_name.
Cookie-режим зберігає перевірки WordPress: manage_options/create_users/promote_users та editable_roles.
Сервісний ключ дозволяє тільки цю явну дію; користувачі залишаються звичайними й видимими.
Автоматичного створення, прихованих користувачів, mu-plugins або файлів API немає.
У Multisite створення адміністраторів вимкнене в обох режимах. Наявні користувачі не змінюються.
Конфлікт логіна або email повертає HTTP 409. Паролі не повертаються та не потрапляють у метадані.
Журнал сайту містить лише логін і час останнього створення та спосіб авторизації.

== Сумісність ==

Звичайна cookie/REST-авторизація та маршрути ping/admins залишаються доступними.
Робота зі статтями й категоріями використовує звичайні права WordPress, окремо від сервісного ключа.
Плагін не обходить CAPTCHA, 2FA, захист хостингу чи вимкнення REST API.
